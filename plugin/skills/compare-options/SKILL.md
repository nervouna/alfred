# Compare options

1. **Pin down the choice.** List the options (at most about six; when the user named none, find the common shortlist and say how you chose it) and the criteria. Use the user's criteria and constraints (budget, region, use case). When they gave none, pick four to six that decide this kind of choice and state them.
2. **Draft the table first**: options as rows, criteria as columns, before any search, so every search fills a cell.
3. **Two sources per option.**
   - Facts from the option's official page: price, plan tier, specs, limits, terms. Note the date you read them and the region or currency they apply to.
   - One independent source (a review, benchmark, or user reports) for what the official page will not say: real performance, support, hidden costs.
4. **Make the cells comparable**: same unit, same currency (give the exchange rate and its date), same billing period, comparable tiers.
5. **Never guess a cell.** Write 未公开 or 未确认, and say what would settle it.
6. **Deliver.**
   - The table, with a source column or a numbered source per cell.
   - The trade-offs in two to four bullets.
   - A one-line recommendation for the user's case, e.g. `选 X：……；如果更看重……则选 Y`.

   A table too wide for a phone goes into a file where the workspace rules put deliverables (with charts or a formal layout, use the html-report skill), and the reply carries the recommendation and the trade-offs.
